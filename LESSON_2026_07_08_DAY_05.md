## 🐍 PYTHON — Control Flow: Branching, Ternaries, `match` & Truthy/Falsy

### Intuition

You've written `if/elif/else` since Day 1 without thinking about it — today's the day it gets a real look, plus three things that make branching more expressive: the ternary (an `if/else` that *returns a value*), `match` (branching on the *shape* of a value, not just equality), and truthy/falsy (the rule Python uses to decide if something counts as "empty" in a boolean context).

### The Essentials

```python
# Ternary — a one-line if/else that produces a value
n = 7
label = "even" if n % 2 == 0 else "odd"

# Works inside comprehensions too — this is where it earns its keep
nums = [-3, 0, 5, -1, 8]
signs = ["positive" if x > 0 else "non-positive" for x in nums]

# match — branch on shape/value instead of a chain of elif
def http_status_label(code):
    match code:
        case 200 | 201 | 204:      # multiple values, one case
            return "success"
        case 400 | 401 | 403 | 404:
            return "client error"
        case 500:
            return "server error"
        case _:                     # the wildcard — always last
            return "unknown"
```

### Truthy / falsy — the rule behind `if not x`

```python
falsy_examples = [0, 0.0, "", [], {}, set(), None, False]
# every one of these is falsy — everything else is truthy

def first_or_default(items, default=None):
    return items[0] if items else default   # "if items" means "if items is non-empty"
```

`if not stock_db:` reads as "if the dict is empty," `if not prices:` reads as "if the list is empty" — you already wrote checks like this on Day 4 without naming the rule. The rule: `0`, `0.0`, `""`, `[]`, `{}`, `set()`, and `None` are falsy; literally everything else (including `"0"` and `[0]`) is truthy.

### Why it matters going forward

`match` on an HTTP status code is a preview of exactly what you're doing in FastAPI today — deciding what to return based on *which category* a value falls into, not one specific equality check. And the truthy/falsy guard (`if not text.strip():`) is what validates the combined task's request body below, in the same "keep it simple, no exceptions yet" style Day 4 used.

## 🧩 DSA — Valid Palindrome *(Easy · Two Pointers)*

**NeetCode:** https://neetcode.io/problems/valid-palindrome

### The Problem

Given a string `s`, return `True` if it's a palindrome once you lowercase everything and ignore non-alphanumeric characters (spaces, punctuation), `False` otherwise.

### Reading the problem like an engineer

Every problem so far has used a hash structure (dict/set) to answer "have I seen this?" This one is different: a palindrome check is really "does the string read the same from both ends, walking inward?" — there's no need to remember anything about characters you've already visited, so a hash structure would be pure overhead. That's the whole point of **two pointers**: one index starts at the front, one at the back, and they walk toward each other.

### Approach 1 — Brute Force (write this first, always)

```python
def is_palindrome_brute(s):
    cleaned = [ch.lower() for ch in s if ch.isalnum()]
    return cleaned == cleaned[::-1]
    # Time:  O(n) — clean once, reverse-compare once
    # Space: O(n) — the cleaned list is a full copy of s
```

### Approach 2 — Two Pointers (the insight)

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():
            left += 1
        elif not s[right].isalnum():
            right -= 1
        elif s[left].lower() != s[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True

    # Time:  O(n) — each pointer moves at most n times total
    # Space: O(1) — two index variables, no extra structure
```

### Walkthrough on `s = "0P"`

```
left=0 ('0'), right=1 ('P')
both alnum -> compare: '0'.lower() != 'p'.lower() -> mismatch
-> return False immediately, no need to scan further
```

### Why the two-pointer approach works

A string is a palindrome exactly when character `i` from the front always matches character `i` from the back, for every `i`. Checking that from both ends simultaneously means you can stop the instant you find a mismatch — you never build an intermediate copy, and you never revisit a character twice. Notice the branching structure of the loop body is today's Python topic in disguise: it's a 4-way `if/elif/elif/else`, deciding "skip left," "skip right," "mismatch — bail," or "match — advance both."

## ⚡ FASTAPI — Response Models & Status Codes (Swagger Deep Dive)

### Intuition

Every endpoint so far has returned "whatever shape felt right" and defaulted to a `200`. Two tools fix both problems at once: `response_model` tells FastAPI (and Swagger) exactly what shape a successful response takes — filtering out anything extra and validating what you send back — and `status_code` lets you say "this was a *creation*, so it's `201`," instead of everything being a `200`.

### The Essentials

```python
from fastapi import FastAPI, status
from pydantic import BaseModel

app = FastAPI()

class StockOut(BaseModel):
    id: int
    ticker: str
    max_profit: int

@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn):
    ...

@app.get("/stocks/{stock_id}/max-profit", response_model=StockOut)
def stock_max_profit(stock_id: int):
    ...
    return {"id": stock_id, "ticker": ..., "max_profit": ...}
```

### What `response_model` actually buys you

Without it, whatever dict you return is whatever the client sees — including any internal fields you forgot were in there. With `response_model=StockOut`, FastAPI validates the outgoing data against `StockOut` and **strips anything not declared on the model**, even if your function returns extra keys. It also means `/docs` shows the *exact* response schema under "Responses" instead of guessing from an example — this is the single biggest lever for making Swagger UI actually useful to someone integrating against your API.

### Status codes worth knowing on sight

```
200 OK              — successful GET/PUT, nothing special to signal
201 Created         — successful POST that created a new resource
204 No Content      — successful DELETE, no body to return
400 Bad Request     — the client sent something invalid
404 Not Found       — the resource doesn't exist
500 Internal Server Error — something broke on your end
```

We're still returning `{"error": "..."}` dicts with an implicit `200` for the not-found cases below — proper `HTTPException` that actually sets `404` on the response is Day 6's topic. Today is only about the *happy path* getting the right shape and the right code.

## 🔗 COMBINED TASK — Wiring All Three

The two-pointer palindrome check becomes a FastAPI endpoint that uses `response_model` for its output shape, `status_code` for the happy path, and the truthy/falsy guard from today's Python block to validate the input — no `HTTPException` needed yet.

```python
# main.py — Day 5 combined endpoint

class PalindromeIn(BaseModel):
    text: str

class PalindromeOut(BaseModel):
    text: str
    is_palindrome: bool

def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():
            left += 1
        elif not s[right].isalnum():
            right -= 1
        elif s[left].lower() != s[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True

@app.post("/palindrome-check", response_model=PalindromeOut, status_code=status.HTTP_200_OK)
def palindrome_check(payload: PalindromeIn):
    if not payload.text.strip():          # truthy/falsy guard
        return {"text": payload.text, "is_palindrome": False}
    return {"text": payload.text, "is_palindrome": is_palindrome(payload.text)}
```

```python
# fastapi/05_response_models/main.py
# Run: uvicorn main:app --reload

from fastapi import FastAPI, status
from pydantic import BaseModel

app = FastAPI(title="Sprint Day 5")


class StockIn(BaseModel):
    ticker: str
    prices: list[int]


class StockOut(BaseModel):
    id: int
    ticker: str
    max_profit: int


stock_db = {}
next_id = 1


@app.get("/")
def root():
    return {"message": "Sprint Day 5 is running.", "day": 5}


@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn):
    global next_id
    stock_id = next_id
    stock_db[stock_id] = payload.model_dump()
    next_id += 1
    return {"id": stock_id, **stock_db[stock_id]}


@app.get("/stocks/{stock_id}/max-profit", response_model=StockOut)
def stock_max_profit(stock_id: int):
    if stock_id not in stock_db:
        return {"error": f"stock {stock_id} not found"}

    prices = stock_db[stock_id]["prices"]
    min_price = prices[0] if prices else 0
    best_profit = 0
    for price in prices[1:]:
        if price < min_price:
            min_price = price
        else:
            best_profit = max(best_profit, price - min_price)

    return {
        "id": stock_id,
        "ticker": stock_db[stock_id]["ticker"],
        "max_profit": best_profit,
    }


class PalindromeIn(BaseModel):
    text: str


class PalindromeOut(BaseModel):
    text: str
    is_palindrome: bool


def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():
            left += 1
        elif not s[right].isalnum():
            right -= 1
        elif s[left].lower() != s[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True


@app.post(
    "/palindrome-check",
    response_model=PalindromeOut,
    status_code=status.HTTP_200_OK,

def palindrome_check(payload: PalindromeIn):
    if not payload.text.strip():
        return {"text": payload.text, "is_palindrome": False}
    return {"text": payload.text, "is_palindrome": is_palindrome(payload.text)}
```

## 🔑 CONCEPT ANSWER

**Question:** "What's the difference between `if value is None` and `if not value` — and why can swapping one for the other introduce a bug?"

**Answer:** `is None` checks for exactly one thing: is this specific object `None`? `if not value` checks for *anything falsy* — `None`, but also `0`, `""`, `[]`, `{}`, and `False`. They only agree when `value` can never legitimately be `0`, `""`, or empty. The bug shows up the moment a falsy-but-valid value enters the picture: if a function parameter can legitimately be `0` (a real quantity, a valid index, a real price), `if not value:` treats that valid `0` the same as a missing value and skips logic that should have run. `is None` only reacts to actual absence, so it's the correct check whenever "not provided" and "provided as zero/empty" need to be treated differently — which is most of the time once real data starts flowing through your code.
