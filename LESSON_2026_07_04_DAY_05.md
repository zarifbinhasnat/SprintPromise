## 🐍 PYTHON — Control Flow: Branching, Ternaries, `match`, Truthiness

### Intuition

Every DSA solution you've written so far branches: `if price < min_price`, `if profit > best`. Today makes that branching vocabulary explicit and adds two tools that compress it — the ternary expression for one-line either/or logic, and `match` for one-value-many-shapes logic — plus the truthy/falsy rules that let you write `if prices:` instead of `if len(prices) > 0:`.

### The Essentials

```python
# if / elif / else — nothing new, but note the ordering rule:
# conditions are checked top to bottom, first match wins, rest are skipped
def grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    else:
        return "F"

# Ternary expression — an if/else that evaluates to a value, not a statement
best_profit = 0
profit = 5
best_profit = profit if profit > best_profit else best_profit
# reads as: "profit, if profit > best_profit is true, else best_profit"

label = "even" if 4 % 2 == 0 else "odd"

# match statement (3.10+) — pattern matching, not just equality checks
def describe(value):
    match value:
        case 0:
            return "zero"
        case int() if value < 0:
            return "negative int"
        case int():
            return "positive int"
        case [first, *rest]:
            return f"list starting with {first}"
        case {"ticker": t}:
            return f"a stock dict for {t}"
        case _:
            return "unknown shape"

# Truthy / falsy — what "if x:" actually checks
falsy_values = [0, 0.0, "", [], {}, set(), None, False]
# everything else is truthy, including "0" (non-empty string) and [0] (non-empty list)

prices = []
if prices:               # False — empty list is falsy
    print("has prices")
else:
    print("no prices yet")   # this runs
```

### Why `match` beats a long `if/elif` chain here

The `int()` and `[first, *rest]` and `{"ticker": t}` cases above aren't just value comparisons — they're checking the **shape** of the data and unpacking it in the same line. An equivalent `if/elif` chain would need `isinstance()` checks plus separate unpacking lines. This matters immediately: today's DSA problem classifies characters by shape (letter vs. digit vs. neither), and today's FastAPI task classifies a validation result the same way.

### Why it matters going forward

`if prices:` (truthy check) is exactly the guard you'll write at the top of nearly every function from here on — "is there anything to process?" — before touching index 0 of a list. You already needed this in Day 4's `prices[0] if prices else 0`; today makes the rule behind that explicit instead of memorized.

## 🧩 DSA — Valid Palindrome *(Easy · Two Pointers)*

**NeetCode:** https://neetcode.io/problems/valid-palindrome

### The Problem

Given a string, determine if it's a palindrome after converting all uppercase letters to lowercase and removing all non-alphanumeric characters. Return `True` or `False`.

### Reading the problem like an engineer

Strip the wrapper: *"Ignoring punctuation and case, does this string read the same forwards and backwards?"* The direct translation is "clean the string, then compare it to its reverse" — that works, but it copies the whole string at least twice. The two-pointer insight: you don't need a cleaned copy at all. Walk one pointer in from the left and one in from the right, skip past anything that isn't alphanumeric, and compare characters as you go. The moment they don't match, you're done — no reversal needed.

### Approach 1 — Brute Force (write this first, always)

```python
def is_palindrome_brute(s):
    cleaned = [ch.lower() for ch in s if ch.isalnum()]
    return cleaned == cleaned[::-1]
    # Time:  O(n) — build cleaned list once, reverse is O(n), compare is O(n)
    # Space: O(n) — the cleaned list and its reverse both live in memory
```

### Approach 2 — Two Pointers (the insight)

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1

    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1

        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True

    # Time:  O(n) — each pointer visits each character at most once
    # Space: O(1) — no copy of the string is ever made
```

### Walkthrough on `s = "A man, a plan, a canal: Panama"`

```
left=0 ('A'), right=29 ('a')  -> both alnum, 'a' == 'a' -> match, move in
left=1 (' '), right=28 ('m')  -> left skips space -> left=2 ('m')
                                   'm' == 'm' -> match, move in
left=3 ('a'), right=27 ('a')  -> 'a' == 'a' -> match
...
(continues skipping spaces/commas/colon, comparing letters)
...
-> pointers cross without a mismatch -> return True
```

### Why the two-pointer approach works

A palindrome check only ever needs to compare position `i` from the front to position `i` from the back — it never needs to look at any character twice. Two pointers converging from opposite ends visit every relevant position exactly once, in the exact order the comparison needs, which is why no extra copy of the string is required. This is the same "no wasted extra pass" instinct as Day 4's running-minimum — just applied to a converging pair of positions instead of one running value.

## ⚡ FASTAPI — Swagger UI Deep Dive, Status Codes & Week 1 Review

### Intuition

You've had `/docs` open since Day 1 to test every endpoint, but today's the day to actually understand what it's showing you — and to start telling it the truth. Every route so far has returned `{"error": "..."}` for a "not found" case while still sending back HTTP `200 OK`, which is a lie: the client has to parse the body to learn the request failed. `status_code` fixes that.

### The Essentials

```python
from fastapi import FastAPI, status
from pydantic import BaseModel
from typing import List

app = FastAPI(title="Sprint Day 5")


class StockIn(BaseModel):
    ticker: str
    prices: List[int]


stock_db = {}
next_id = 1


# status_code on the decorator sets the DEFAULT success status for this route.
# 201 Created is the correct code for "a new resource now exists" — not 200.
@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn):
    global next_id
    stock_id = next_id
    stock_db[stock_id] = payload.model_dump()
    next_id += 1
    return {"id": stock_id, **stock_db[stock_id]}


# Response(status_code=...) lets a single function return DIFFERENT codes
# depending on what happened inside it — the "not found" case finally
# stops lying about being a 200.
from fastapi import Response


@app.get("/stocks/{stock_id}")
def get_stock(stock_id: int, response: Response):
    if stock_id not in stock_db:
        response.status_code = status.HTTP_404_NOT_FOUND
        return {"error": f"stock {stock_id} not found"}
    return {"id": stock_id, **stock_db[stock_id]}
```

### What Swagger UI (`/docs`) is actually showing you

- **Every route grouped by tag**, with method badges (`GET` green, `POST` blue, `DELETE` red) — the badge color is a status-code convention worth learning, since you'll see the same green/blue/red split in the response section.
- **"Try it out"** builds a real HTTP request from the schema your `BaseModel` defines — this is why `StockIn` shows up as an editable JSON form instead of you having to know the shape by memory.
- **The Responses panel** at the bottom of each route shows the status codes *your code declares* — this is empty/generic until you start setting `status_code`, which is exactly what today's change adds.
- **`/redoc`** is the same schema rendered as static reference docs instead of an interactive tester — worth knowing it exists for when you want to hand someone documentation instead of a playground.

## 🔗 COMBINED TASK — Wiring All Three

The two-pointer palindrome check becomes an endpoint, a `match` statement classifies the result into a human-readable reason, and the response finally uses the right status code instead of a lying `200`.

```python
# main.py — Day 5 combined endpoint

from fastapi import FastAPI, Response, status
from pydantic import BaseModel

app = FastAPI(title="Sprint Day 5")


class TextIn(BaseModel):
    text: str


def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True


@app.post("/strings/palindrome-check")
def palindrome_check(payload: TextIn, response: Response):
    text = payload.text

    # truthy/falsy check from today's Python block — an empty/whitespace-only
    # string isn't a real input, so it's a client error, not a valid check.
    if not text.strip():
        response.status_code = status.HTTP_400_BAD_REQUEST
        return {"error": "text must not be empty"}

    result = is_palindrome(text)

    # match statement replaces what would otherwise be an if/elif chain
    # classifying the result by shape (bool value + length)
    match (result, len(text)):
        case (True, n) if n <= 1:
            reason = "trivially a palindrome (0 or 1 character)"
        case (True, _):
            reason = "reads the same forwards and backwards"
        case (False, _):
            reason = "does not read the same forwards and backwards"

    return {"text": text, "is_palindrome": result, "reason": reason}
```

## 🔑 CONCEPT ANSWER

**Question:** "Why is `[]` falsy but `[0]` truthy — isn't `0` also falsy?"

**Answer:** Truthiness of a container is about **emptiness**, not about the truthiness of what's inside it. `bool()` on a list checks `len(list) == 0` — an empty list has nothing to iterate over, so `if prices:` reads as "is there anything here to process?" `[0]` has one element, so its length is `1`, which makes the list itself truthy, even though that one element (`0`) would be falsy *if you evaluated it on its own*. The container's truthiness and its contents' truthiness are two separate questions — `if prices:` is asking "does this list exist and have items," while `if prices[0]:` would be asking "is the first item non-zero." Mixing those up is a classic bug source: `if prices[0]:` skips a stock whose first price happens to be `0`, while `if prices:` correctly only skips a stock with *no* price history at all.
