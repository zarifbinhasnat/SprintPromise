## 🐍 PYTHON — Loops

### Intuition

You've written `for price in prices:` a dozen times without thinking about it. Today is about the three companions that make loops precise instead of just "walk the list": `range()` when you need indices instead of values, `enumerate()` when you need both, and `zip()` when you need to walk two sequences together. Plus `break`/`continue` for controlling the walk itself, and `while` for when you don't know the length in advance.

### The Essentials

```python
# range() — when you need indices, not values
for i in range(5):          # 0, 1, 2, 3, 4
    print(i)

for i in range(2, 10, 2):   # start, stop, step -> 2, 4, 6, 8
    print(i)

# enumerate() — index AND value, without a manual counter
prices = [7, 1, 5, 3, 6, 4]
for i, price in enumerate(prices):
    print(f"day {i}: ${price}")

# zip() — walk two sequences together, stops at the shorter one
tickers = ["AAA", "BBB", "CCC"]
prices  = [10, 20, 30]
for ticker, price in zip(tickers, prices):
    print(f"{ticker}: ${price}")

# break — stop the loop entirely
def first_negative(nums):
    for n in nums:
        if n < 0:
            return n
    return None
    # (a `return` is the cleanest break here, but `break` matters when
    #  you still need code to run *after* the loop, using the leftover state)

# continue — skip this iteration, keep going
def sum_positive(nums):
    total = 0
    for n in nums:
        if n < 0:
            continue
        total += n
    return total

# while — when the stop condition isn't "walked the whole list"
def countdown(n):
    while n > 0:
        print(n)
        n -= 1
    print("liftoff")
```

### `for...else` — the one nobody teaches

```python
def has_duplicate_pair(nums, target_sum):
    for i, a in enumerate(nums):
        for b in nums[i + 1:]:
            if a + b == target_sum:
                break
        else:
            continue   # inner loop didn't break — keep scanning
        break          # inner loop DID break — stop outer loop too
    # the else on a for loop runs only if the loop completed without break
```

You'll rarely reach for `for...else` day to day, but recognizing it in someone else's code — instead of assuming it's a typo — is worth the five minutes it takes to learn.

## 🧩 DSA — Longest Common Prefix *(Easy · Strings)*

**LeetCode:** https://leetcode.com/problems/longest-common-prefix/

### The Problem

Given an array of strings, find the longest string that is a prefix of every string in the array. Return `""` if there is no common prefix.

### Reading the problem like an engineer

Strip the wrapper: *"How far can I walk into the first word before some other word in the list disagrees?"* That's a loop with an early exit — exactly today's Python theme. Treat the first string as your candidate prefix, and shrink it every time you find a word that doesn't start with it.

### Approach 1 — Brute Force (write this first, always)

```python
def longest_common_prefix_brute(strs):
    if not strs:
        return ""
    prefix = strs[0]
    for s in strs[1:]:
        while not s.startswith(prefix):
            prefix = prefix[:-1]
            if not prefix:
                return ""
    return prefix
    # Time:  O(n * m) — n strings, up to m chars trimmed off one at a time
    # Space: O(1) extra (prefix is a slice of existing data)
```

### Approach 2 — Vertical Scan (the insight)

```python
def longest_common_prefix(strs):
    if not strs:
        return ""

    for i, char in enumerate(strs[0]):
        for s in strs[1:]:
            if i >= len(s) or s[i] != char:
                return strs[0][:i]
    return strs[0]

    # Time:  O(n * m) — same worst case, but exits the instant of first mismatch
    # Space: O(1) extra
```

### Walkthrough on `["flower", "flow", "flight"]`

```
i=0, char='f' -> "flow"[0]='f' ok, "flight"[0]='f' ok
i=1, char='l' -> "flow"[1]='l' ok, "flight"[1]='l' ok
i=2, char='o' -> "flow"[2]='o' ok, "flight"[2]='i' != 'o' -> return strs[0][:2] = "fl"
```

### Why the vertical scan is the one worth internalizing

Both approaches are O(n*m) worst case, so again the win isn't asymptotic — it's that the vertical scan stops at the very first mismatched *character* across all words, while the brute force keeps re-scanning whole strings with `.startswith()` on every trim. The real skill: `enumerate()` here isn't decoration, it's what lets you check "does every other word still agree at this exact index" — today's loop vocabulary applied directly.

## ⚡ FASTAPI — Real Error Handling with `HTTPException`

### Intuition

Since Day 3 every "not found" case has returned `{"error": "..."}` with a silent `200 OK` — which is actually a lie to the client, since `200` means success. `HTTPException` is how you tell FastAPI "stop, this request failed, and here's the real status code and message to send back."

### The Essentials

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()

stock_db = {}

@app.get("/stocks/{stock_id}")
def get_stock(stock_id: int):
    if stock_id not in stock_db:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"stock {stock_id} not found",
        )
    return stock_db[stock_id]
    # A 404 in Swagger now actually shows as a 404 response, with a proper
    # {"detail": "stock 1 not found"} body — no more silently-lying 200s.
```

### Why `raise` instead of `return`

`return {"error": "..."}` still sends a `200 OK` — the HTTP layer thinks everything went fine, even though your JSON body says otherwise. Any client checking `if response.status_code == 200:` (which is the normal thing to check) gets fooled. `raise HTTPException(...)` short-circuits the function immediately and tells FastAPI's framework layer to build a response with the *real* status code — the failure is visible at the protocol level, not buried inside the body.

## 🔗 COMBINED TASK — Wiring All Three

Every "not found" branch from Days 3–5 gets upgraded to a real `HTTPException`, and the Longest Common Prefix walk (today's loop pattern) becomes an endpoint that finds the shared prefix across every ticker currently in the store.

```python
# main.py — Day 6 combined endpoint

@app.get("/stocks/common-prefix")
def stocks_common_prefix():
    tickers = [record["ticker"] for record in stock_db.values()]
    if not tickers:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="no stocks yet")

    prefix = tickers[0]
    for i, char in enumerate(prefix):
        for ticker in tickers[1:]:
            if i >= len(ticker) or ticker[i] != char:
                return {"tickers": tickers, "common_prefix": prefix[:i]}
    return {"tickers": tickers, "common_prefix": prefix}


@app.get("/stocks/{stock_id}")
def get_stock(stock_id: int):
    if stock_id not in stock_db:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"stock {stock_id} not found")
    return {"id": stock_id, **stock_db[stock_id]}
```

```python
# fastapi/06_error_handling/main.py
# Run: uvicorn main:app --reload

from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel
from typing import List

app = FastAPI(title="Sprint Day 6")


class StockIn(BaseModel):
    ticker: str
    prices: List[int]


stock_db = {}
next_id = 1


@app.get("/")
def root():
    return {"message": "Sprint Day 6 is running.", "day": 6}


@app.get("/stocks")
def list_stocks():
    return stock_db


@app.get("/stocks/common-prefix")
def stocks_common_prefix():
    tickers = [record["ticker"] for record in stock_db.values()]
    if not tickers:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="no stocks yet")

    prefix = tickers[0]
    for i, char in enumerate(prefix):
        for ticker in tickers[1:]:
            if i >= len(ticker) or ticker[i] != char:
                return {"tickers": tickers, "common_prefix": prefix[:i]}
    return {"tickers": tickers, "common_prefix": prefix}


@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn):
    global next_id
    stock_id = next_id
    stock_db[stock_id] = payload.model_dump()
    next_id += 1
    return {"id": stock_id, **stock_db[stock_id]}


@app.get("/stocks/{stock_id}")
def get_stock(stock_id: int):
    if stock_id not in stock_db:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"stock {stock_id} not found")
    return {"id": stock_id, **stock_db[stock_id]}


@app.put("/stocks/{stock_id}")
def update_stock(stock_id: int, payload: StockIn):
    if stock_id not in stock_db:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"stock {stock_id} not found")
    stock_db[stock_id] = payload.model_dump()
    return {"id": stock_id, **stock_db[stock_id]}


@app.delete("/stocks/{stock_id}")
def delete_stock(stock_id: int):
    if stock_id not in stock_db:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"stock {stock_id} not found")
    removed = stock_db.pop(stock_id)
    return {"deleted_id": stock_id, "ticker": removed["ticker"]}
```

## 🔑 CONCEPT ANSWER

**Question:** "What's the actual difference between `break` and `continue`, and why does neither one work inside a list comprehension?"

**Answer:** `break` exits the loop entirely — no more iterations run, and control moves to whatever comes after the loop. `continue` only skips the *rest of the current iteration* — the loop keeps going with the next item. Neither works inside a list comprehension because a comprehension isn't a loop statement, it's an expression that builds a value; there's no loop body for `break`/`continue` to attach to, only a single per-element expression (and an optional `if` filter, which is how you approximate "skip this one" — the `if` clause in `[x for x in nums if x > 0]` is the comprehension's answer to `continue`, but there's no equivalent for early-exiting the whole comprehension like `break` does).
