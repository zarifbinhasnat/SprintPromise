## 🐍 PYTHON — Type Hints Basics

### Intuition

`def add(a: int, b: int) -> int:` has been in this track's code since Day 3, unnamed. A type hint documents what a function expects and returns — Python does **not** enforce it at runtime, but your editor, `mypy`, and (critically, starting today's FastAPI section) FastAPI itself all read and act on it.

### The Essentials

```python
def add(a: int, b: int) -> int:
    return a + b

add(2, 3)      # 5 — as expected
add("2", "3")  # "23" — Python still RUNS this. Hints are not enforced at runtime.
```

That last line is the one thing to internalize: type hints are documentation plus tooling, not a runtime guardrail. `mypy` would flag `add("2", "3")` as an error before you ever ran it — but bare Python won't stop you.

### Collection types — what's inside, not just "a list"

```python
def total_price(prices: list[int]) -> int:
    return sum(prices)

def ticker_lookup(prices_by_ticker: dict[str, list[int]]) -> list[str]:
    return list(prices_by_ticker.keys())
```

`list[int]` says more than `list` — it says *a list of ints specifically*, which is what lets your editor autocomplete `.bit_length()` on an element instead of guessing.

### `Optional[X]` — "X or None," made explicit

```python
from typing import Optional

def find_ticker(tickers: list[str], target: str) -> Optional[int]:
    for i, ticker in enumerate(tickers):
        if ticker == target:
            return i
    return None

index = find_ticker(["ACME", "ZED"], "ZED")
if index is not None:      # the hint is WHY this check exists
    print(f"found at index {index}")
```

`Optional[int]` (the same thing as `int | None`) documents a real branch every caller has to handle — it's the type-hint equivalent of today's DSA problem returning `-1` when nothing's found, made explicit instead of a bare integer that might be a sentinel.

### Why FastAPI leans on these so heavily

Every route parameter and Pydantic model since Day 3 — `StockIn`, `stock_id: int`, `List[int]` on `prices` — has been a type hint. FastAPI reads them at import time to build request validation, response schemas, *and* the interactive Swagger docs you've been testing against since Day 5. The hints aren't documentation there — they're the entire mechanism.

## 🧩 DSA — Binary Search *(Easy · Binary Search)*

**NeetCode:** https://neetcode.io/problems/binary-search

### The Problem

Given a **sorted** array of integers and a target value, return its index, or `-1` if it's not present.

### Reading the problem like an engineer

Every search in this track so far — Two Sum, Contains Duplicate, Valid Anagram — either scans linearly or trades space for a single O(1) lookup via a dict. This is the first problem where the input's sortedness is itself the tool: because the array is sorted, checking the middle element doesn't just check one value — it tells you which *half* the target must be in, if it's there at all, eliminating the other half without ever looking at it.

### Approach 1 — Brute Force (write this first, always)

```python
def binary_search_brute(nums, target):
    for i, val in enumerate(nums):
        if val == target:
            return i
    return -1
    # Time:  O(n) — checks every element in the worst case
    # Space: O(1)
```

Correct, and doesn't even require the array to be sorted — which is exactly the sign it's not using all the information the problem gives you.

### Approach 2 — Binary Search (the insight)

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1     # target must be to the right — discard the left half
        else:
            right = mid - 1    # target must be to the left — discard the right half
    return -1
    # Time:  O(log n) — the search space halves every iteration
    # Space: O(1) — two pointers, no extra structure
```

### Walkthrough on `nums = [-10, -3, 0, 5, 9, 12, 20, 33]`, `target = 9`

```
left=0, right=7
mid=3 -> nums[3]=5 < 9  -> too small, discard left half -> left=4
left=4, right=7
mid=5 -> nums[5]=12 > 9 -> too big, discard right half -> right=4
left=4, right=4
mid=4 -> nums[4]=9 == 9 -> FOUND at index 4
```

Three comparisons found the target in an 8-element array — a linear scan could have taken up to 8. At a million elements, binary search still takes about 20 comparisons; a linear scan could take a million.

### Why binary search, specifically — the first O(log n) in this track

Every algorithm through Day 13 has been O(n) at best on its main input — one pass, one visit per element. Binary search is qualitatively different: each comparison doesn't just make progress, it **halves the remaining problem**. That's what "logarithmic" means concretely — the number of comparisons needed to search `n` elements grows by only 1 every time `n` *doubles*, instead of growing proportionally to `n` itself.

## ⚡ FASTAPI — Request Logging

### Intuition

Day 8 introduced middleware as "code that runs around every request." Day 12 used it to count requests; Day 13 used `CORSMiddleware` to attach headers. Today's middleware answers the question none of the previous six days' apps could: *what actually happened, once the response is already sent?* Request logging records method, path, status code, and how long it took — for every request, without touching a single route.

### The Essentials

```python
import logging
import time

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")
logger = logging.getLogger("sprint")

@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    duration_ms = (time.perf_counter() - start) * 1000
    logger.info(f"{request.method} {request.url.path} -> {response.status_code} ({duration_ms:.2f}ms)")
    return response
```

The timing only works because of `call_next` — everything before it runs before the route handler, everything after runs after, so `response.status_code` is only available once the route has actually finished, and the elapsed time genuinely measures the route's own work, not just the middleware's overhead.

### Why this belongs in middleware, not in every route

The alternative — adding a `logger.info(...)` line inside every route body — means remembering to do it in every new route forever, and it can't measure the response's own status code without extra bookkeeping (was it a 200? did an exception handler turn it into a 404?). One middleware function, registered once, sees every request and every response — including the ones exception handlers rewrote — with zero per-route code.

### FastAPI — Full `main.py`

```python
# fastapi/14_request_logging/main.py
# Run: uvicorn main:app --reload

import logging
import time
from contextlib import asynccontextmanager
from fastapi import FastAPI, Depends, Request, status
from fastapi.responses import JSONResponse
from pydantic import BaseModel

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")
logger = logging.getLogger("sprint")

app_state = {}


def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1


@asynccontextmanager
async def lifespan(app: FastAPI):
    app_state["request_count"] = 0
    yield
    logger.info(f"shutdown: handled {app_state['request_count']} requests")
    app_state.clear()


app = FastAPI(title="Sprint Day 14", lifespan=lifespan)


class StockNotFoundError(Exception):
    def __init__(self, ticker: str):
        self.ticker = ticker


class StockIn(BaseModel):
    ticker: str
    prices: list[int]


tickers_sorted: list[str] = []


def get_stock_or_404(ticker: str) -> int:
    idx = binary_search(tickers_sorted, ticker)
    if idx == -1:
        raise StockNotFoundError(ticker)
    return idx


@app.exception_handler(StockNotFoundError)
def stock_not_found_handler(request: Request, exc: StockNotFoundError):
    return JSONResponse(
        status_code=status.HTTP_404_NOT_FOUND,
        content={"error": "stock_not_found", "detail": f"ticker {exc.ticker!r} not found"},
    )


@app.middleware("http")
async def log_requests(request: Request, call_next):
    app_state["request_count"] += 1
    start = time.perf_counter()
    response = await call_next(request)
    duration_ms = (time.perf_counter() - start) * 1000
    logger.info(f"{request.method} {request.url.path} -> {response.status_code} ({duration_ms:.2f}ms)")
    return response


@app.get("/")
def root() -> dict:
    return {"message": "Sprint Day 14 is running.", "day": 14, "requests_so_far": app_state["request_count"]}


@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn) -> dict:
    if payload.ticker not in tickers_sorted:
        tickers_sorted.append(payload.ticker)
        tickers_sorted.sort()
    return {"ticker": payload.ticker, "prices": payload.prices}


@app.get("/stocks/{ticker}")
def get_stock(ticker: str, idx: int = Depends(get_stock_or_404)) -> dict:
    return {"ticker": tickers_sorted[idx], "index": idx}
```

## 🔑 CONCEPT ANSWER

**Question:** "If type hints aren't enforced at runtime, what is FastAPI actually doing with `stock_id: int` in a route signature that makes a non-integer path segment fail with a 422?"

**Answer:** FastAPI itself doesn't get a runtime exemption from "Python doesn't enforce hints" — what's actually happening is that FastAPI reads the type hint at import time (using Python's introspection, not by relying on Python to enforce it) and uses it to *build a Pydantic validator* for that parameter. When a request comes in, FastAPI hands the raw path segment (always a string, since URLs are text) to that validator, which is Pydantic actively trying to convert `"abc"` to an `int` and failing — that failure is what produces the 422, with Pydantic's own error detail describing exactly which field and why. So the hint isn't enforced by the Python interpreter the way it would be in a statically-typed language; it's read once by FastAPI's startup machinery and turned into real, running validation code that Pydantic executes on every request. That's the same mechanism that's been building your Swagger docs and validating `StockIn` bodies since Day 3 — this is the first day it's been named directly.
