## 🐍 PYTHON — Lambdas, `map()`, `filter()`, `sorted(key=...)`

### Intuition

A `lambda` is a function with no name, restricted to a single expression — `lambda n: n * n` is the same thing as `def square(n): return n * n`, minus the name. On its own that's not very useful; what makes it worth learning is passing one directly into another function that expects a function as an argument, which is exactly what `sorted()`, `map()`, and `filter()` do.

### The Essentials

```python
# lambda — anonymous one-expression function
square = lambda n: n * n
square(5)   # 25

# Lambdas as KEY functions — this is the whole reason they're worth learning
nums = [5, 2, 8, 1, 9]
sorted(nums, key=lambda n: -n)              # [9, 8, 5, 2, 1] — descending, no separate def needed

stocks = [{"ticker": "AAA", "price": 42}, {"ticker": "BBB", "price": 10}]
sorted(stocks, key=lambda s: s["price"])    # sort dicts by one field, one line

# map() — apply a function to every element
prices = [10, 20, 30]
list(map(lambda p: p * 2, prices))          # [20, 40, 60]

# filter() — keep only elements where the function returns True
list(filter(lambda n: n % 2 == 0, nums))    # [2, 8]
```

### Why the comprehension usually wins anyway

```python
# Same result, two styles:
evens_comp      = [n for n in nums if n % 2 == 0]
evens_mapfilter = list(filter(lambda n: n % 2 == 0, nums))
# Prefer the comprehension for simple transforms/filters (Day 9) — it reads
# left to right and doesn't need a lambda at all. Lambda earns its keep
# specifically as a KEY function for sorted()/max()/min(), where there's no
# comprehension equivalent — you can't write sorted() as a comprehension.
```

A lambda is restricted to one expression on purpose — no `if/elif/else` chains, no loops, no assignment. The moment your logic needs more than one expression, that's a signal to write a real `def` function instead.

## 🧩 DSA — Valid Parentheses *(Easy · Stack)*

**NeetCode:** https://neetcode.io/problems/valid-parentheses

### The Problem

Given a string containing only `(){}[]`, determine whether every opening bracket is closed by the same type of bracket, in the correct order.

### Reading the problem like an engineer

Strip the wrapper: *"As I scan left to right, does everything I open eventually get closed, most-recent-first?"* That "most-recent-first" is the whole reason this needs a new data structure — every problem so far (two pointers, running trackers, dict/set lookups) has been order-independent or two-ended. This one specifically needs *last opened, first closed* — which is exactly what a stack gives you for free.

### Approach 1 — Brute Force (write this first, always)

```python
def is_valid_brute(s):
    prev = None
    while prev != s:
        prev = s
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return s == ""
    # Time:  O(n^2) — up to n/2 passes, each an O(n) replace
    # Space: O(n) — a new string is built on every replace call
```

Repeatedly deleting the innermost matched pair actually works — it's just slow, because every deletion re-scans the whole string.

### Approach 2 — Stack (the insight)

```python
def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return not stack

    # Time:  O(n) — one pass
    # Space: O(n) — stack holds up to n/2 open brackets
```

### Walkthrough on `s = "{[()]}"`

```
stack=[]
'{' -> opening -> push -> stack=['{']
'[' -> opening -> push -> stack=['{', '[']
'(' -> opening -> push -> stack=['{', '[', '(']
')' -> closing, pairs[')']='(' , stack.pop()='(' match -> stack=['{', '[']
']' -> closing, pairs[']']='[' , stack.pop()='[' match -> stack=['{']
'}' -> closing, pairs['}']='{' , stack.pop()='{' match -> stack=[]
-> stack empty -> True
```

### Why a stack, specifically

`stack.pop()` always returns the *most recently pushed* item — LIFO, last in first out — which is precisely the rule nesting requires: the bracket you close next must be the one you opened most recently. A queue (first in, first out) would give you the wrong bracket back. This is the first problem in this track where the two-pointer and running-tracker patterns from Days 1–9 genuinely don't apply — a new tool for a new shape of problem.

### The Essentials — the bug review days are for

```python
# Static paths must be registered BEFORE dynamic ones that could shadow them.
# GET /stocks/{stock_id} expects an int — but Starlette matches the PATH
# STRUCTURE first and only tries the int conversion after, so if this were
# declared before /stocks/sorted, a request to /stocks/sorted would hit
# /stocks/{stock_id} first, fail to convert "sorted" to an int, and 422
# instead of ever reaching your sorted-list logic.

@app.get("/stocks/sorted")      # <- must come first
def sorted_stocks(by: str = "price"):
    ...

@app.get("/stocks/{stock_id}")  # <- or this swallows the request above
def get_stock(stock_id: int, stock: dict = Depends(get_stock_or_404)):
    ...
```

This is exactly the kind of mistake that's invisible when you write routes one at a time (Days 1–9) and only surfaces once you have enough of them to collide — which is the entire point of a review day.

### Reusing today's DSA as a real validator

```python
def is_valid_parentheses(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        elif ch in pairs.values():
            stack.append(ch)
    return not stack

def validate_notes(payload: StockIn):
    if payload.notes and not is_valid_parentheses(payload.notes):
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail="notes has unbalanced brackets")
    return payload
```

`is_valid_parentheses` isn't just an interview answer — dropped into a `Depends()`, it becomes a real input validator, the same reuse instinct Day 9 used for `get_stock_or_404`.

## 🔗 COMBINED TASK — Wiring All Three

A new optional `notes` field on `StockIn` gets checked for balanced brackets by today's stack algorithm, running as a `Depends()` before `create_stock` — reusing Day 9's dependency pattern — and a new `/stocks/sorted` endpoint sorts the whole store with today's `sorted(key=lambda ...)`, ordering by average price or by ticker.

```python
# main.py — Day 10 combined endpoints

def is_valid_parentheses(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        elif ch in pairs.values():
            stack.append(ch)
    return not stack


def validate_notes(payload: StockIn):
    if payload.notes and not is_valid_parentheses(payload.notes):
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail="notes has unbalanced brackets")
    return payload


@app.get("/stocks/sorted")
def sorted_stocks(by: str = "price"):
    def avg_price(item):
        return sum(item[1]["prices"]) / len(item[1]["prices"])

    key_fn = avg_price if by == "price" else (lambda item: item[1]["ticker"])
    ordered = sorted(stock_db.items(), key=key_fn)
    return [{"id": sid, **data} for sid, data in ordered]


@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn = Depends(validate_notes)):
    global next_id
    stock_id = next_id
    stock_db[stock_id] = payload.model_dump()
    next_id += 1
    return {"id": stock_id, **stock_db[stock_id]}
```

# Run: uvicorn main:app --reload

from fastapi import FastAPI, Depends, HTTPException, status
from pydantic import BaseModel
from typing import List, Optional

app = FastAPI(title="Sprint Day 10")


class StockIn(BaseModel):
    ticker: str
    prices: List[int]
    notes: Optional[str] = None


stock_db = {}
next_id = 1


def is_valid_parentheses(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        elif ch in pairs.values():
            stack.append(ch)
    return not stack


def validate_notes(payload: StockIn):
    if payload.notes and not is_valid_parentheses(payload.notes):
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail="notes has unbalanced brackets")
    return payload


def get_stock_or_404(stock_id: int):
    if stock_id not in stock_db:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"stock {stock_id} not found")
    return stock_db[stock_id]


@app.get("/")
def root():
    return {"message": "Sprint Day 10 is running.", "day": 10}


@app.get("/stocks")
def list_stocks():
    return stock_db


@app.get("/stocks/sorted")
def sorted_stocks(by: str = "price"):
    def avg_price(item):
        return sum(item[1]["prices"]) / len(item[1]["prices"])

    key_fn = avg_price if by == "price" else (lambda item: item[1]["ticker"])
    ordered = sorted(stock_db.items(), key=key_fn)
    return [{"id": sid, **data} for sid, data in ordered]


@app.post("/stocks", status_code=status.HTTP_201_CREATED)
def create_stock(payload: StockIn = Depends(validate_notes)):
    global next_id
    stock_id = next_id
    stock_db[stock_id] = payload.model_dump()
    next_id += 1
    return {"id": stock_id, **stock_db[stock_id]}


@app.get("/stocks/{stock_id}")
def get_stock(stock_id: int, stock: dict = Depends(get_stock_or_404)):
    return stock


@app.put("/stocks/{stock_id}")
def update_stock(stock_id: int, payload: StockIn, stock: dict = Depends(get_stock_or_404)):
    stock_db[stock_id] = payload.model_dump()
    return {"id": stock_id, **stock_db[stock_id]}


@app.delete("/stocks/{stock_id}")
def delete_stock(stock_id: int, stock: dict = Depends(get_stock_or_404)):
    del stock_db[stock_id]
    return {"deleted_id": stock_id, "ticker": stock["ticker"]}

## 🔑 CONCEPT ANSWER

**Question:** "Why is a lambda restricted to a single expression, and why does that make it the wrong tool for anything beyond a short key or callback function?"

**Answer:** Python's grammar defines a lambda's body as a single expression, not a block of statements — there's no room in the syntax for an assignment, a `print()` call, an `if/elif/else` chain, or a loop inside one. That's a deliberate restriction, not an oversight: it keeps a lambda small enough to write inline as an argument to another function (`sorted(key=...)`, `filter(...)`) without breaking the flow of the call it's embedded in. The moment logic needs more than one expression — multiple steps, branching, a variable you want to reuse — a lambda has no syntax to express that, so you write a normal `def` function instead and pass its name. The rule of thumb: if you can't say it in one line without a semicolon-style hack, it doesn't belong in a lambda.
