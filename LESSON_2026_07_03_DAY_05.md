## 🐍 PYTHON — Control Flow *(~25 min)*

### Intuition

Every program so far has run top-to-bottom with no decisions. Control flow is how code *branches*: do this if true, that if false. Python gives you four tools for it, and picking the right one is as much the skill as writing it correctly.

### The Essentials

```python
# if / elif / else — the workhorse
age = 20
if age < 13:
    category = "child"
elif age < 20:
    category = "teen"
else:
    category = "adult"

# Ternary expression — an if/else that fits in one line, when both branches
# are simple values (not multi-line logic)
label = "adult" if age >= 20 else "minor"

# match statement (Python 3.10+) — pattern matching, best when you're
# checking one value against many discrete cases
status_code = 404
match status_code:
    case 200:
        print("OK")
    case 400 | 404:          # the | means "either of these"
        print("Client error")
    case code if code >= 500:  # guard clause — extra condition on the match
        print("Server error")
    case _:                  # the wildcard — like `else`
        print("Unknown")

# Truthy / falsy — every value has a boolean "truthiness" even if it's
# not literally True/False. Falsy: 0, "", None, [], {}, set(). Everything
# else is truthy.
text = "  "
if not text.strip():
    print("text is empty or whitespace-only")
```

### Why it matters going forward

`if not text.strip()` is the exact truthy/falsy check you'll use today in FastAPI to reject empty input — and the ternary (`"palindrome" if result else "not a palindrome"`) is how you'll turn today's DSA boolean result into a human-readable string in one line instead of a 4-line if/else.

## 🧩 DSA — Valid Palindrome *(Easy · Two Pointers · ~35 min)*

**NeetCode:** https://neetcode.io/problems/valid-palindrome

### The Problem

Given a string, determine if it's a palindrome, considering only alphanumeric characters and ignoring case. `"A man, a plan, a canal: Panama"` → `true`. `"race a car"` → `false`.

### Reading the problem like an engineer

Strip the wrapper: *"if I stand at both ends of the string and walk inward, do the letters always match, ignoring punctuation and case?"* This is your first pattern that isn't hash-based — no dict, no set. Two pointers, walking toward each other, is its own tool: reach for it whenever the question is about comparing from both ends of a sequence at once.

### Approach 1 — Brute Force (write this first, always)

```python
def is_palindrome_brute(s):
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]
    # Time:  O(n) — one pass to clean, one to reverse and compare
    # Space: O(n) — cleaned is a full copy of the filtered string
```

### Approach 2 — Two Pointers, No Extra Space (the insight)

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

    # Time:  O(n) — each pointer crosses the string at most once
    # Space: O(1) — two indices, no cleaned copy at all
```

### Walkthrough on `"race a car"`

```
left=0 ('r'), right=9 ('r')  -> match, move both in
left=1 ('a'), right=8 ('a')  -> match, move both in
left=2 ('c'), right=7 ('c')  -> match, move both in
left=3 ('e'), right=6 ('a')  -> 'e' != 'a' -> return False
```

### Why the two-pointer works

Both pointers only ever move inward, and every comparison is final — once `s[left] != s[right]`, no amount of further walking can fix it, so you can return `False` immediately. The inner `while` loops skip punctuation *in place*, which is what makes this O(1) space: Approach 1 pays for a cleaned copy; Approach 2 pays nothing, just a few extra pointer nudges.

## ⚡ FASTAPI — Status Codes & Swagger UI Deep-Dive *(~25 min)*

### Intuition

You've been using `/docs` since Day 1 without really looking at it. Today: understand what's actually generating that page, and learn to control the one thing you've been leaving to chance — the HTTP status code your endpoint returns.

### The Essentials

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()

# status_code= sets what's returned on success (default is always 200)
@app.get("/items/{item_id}", status_code=status.HTTP_200_OK)
def get_item(item_id: int):
    ...

# HTTPException — the correct way to return an error status, replacing
# yesterday's {"error": "..."} placeholder
@app.get("/items/{item_id}")
def get_item(item_id: int):
    if item_id not in db:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"item {item_id} not found",
        )
    return db[item_id]
```

`status.HTTP_400_BAD_REQUEST` is just the integer `400` with a readable name — using the constant instead of the raw number is the convention because it's self-documenting and autocompletes.

### Swagger UI — what you've actually been looking at

Every route's `summary`, `tags`, and docstring feed directly into `/docs`:

```python
@app.get("/palindrome-check/{text}", tags=["palindrome"], summary="Check whether a string is a palindrome")
def palindrome_check(text: str):
    ...
```

`tags=[...]` groups routes into collapsible sections in Swagger. `summary=` is the one-line description shown next to the route. FastAPI builds this whole page from your function signatures and type hints automatically — that's the actual point of using Pydantic models and type hints everywhere, not just "so it works."

## 🔗 COMBINED TASK — Wiring All Three

The two-pointer palindrome check becomes a FastAPI endpoint, using today's ternary for the response and `HTTPException` for bad input.

```python
# fastapi/05_status_codes_swagger/main.py

from fastapi import FastAPI, HTTPException, status

app = FastAPI()

def is_palindrome(s: str) -> bool:
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

@app.get("/palindrome-check/{text}", status_code=status.HTTP_200_OK, tags=["palindrome"])
def palindrome_check(text: str):
    if not text.strip():                      # truthy/falsy check from today's Python block
        raise HTTPException(status_code=status.HTTP_400_BAD_REQUEST, detail="text must not be empty or whitespace-only")

    result = is_palindrome(text)               # today's two-pointer DSA solution
    verdict = "palindrome" if result else "not a palindrome"   # today's ternary
    return {"text": text, "is_palindrome": result, "verdict": verdict}
```

## 🔑 CONCEPT ANSWER

**Question:** "Why is `if not text:` usually preferred over `if text == \"\":` or `if len(text) == 0:` in Python?"

**Answer:** `if not text:` uses Python's truthy/falsy protocol, which every built-in container (`str`, `list`, `dict`, `set`) implements consistently — empty means falsy, non-empty means truthy. `text == ""` only catches the exact empty string, missing `None` entirely (`None == ""` is `False`, so a `None` value would silently slip past that check and crash later). `len(text) == 0` works but is more code to express the same idea, and breaks if `text` is ever `None` (`len(None)` raises `TypeError`). `if not text:` handles empty string, `None`, and any other falsy value in one guard — which is exactly why it's the idiomatic choice, and exactly what today's FastAPI endpoint uses to reject bad input.
